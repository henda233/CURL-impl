# 训练日志记录 —— 技术文档

> 记录 ac 与 sac 训练过程"控制台全量输出落盘"特性的需求、设计、接口与验证。需求见 `docs/functions/训练日志记录.md`；源码改动 `src/ac/log_tee.py`、`src/sac/log_tee.py` 与两个 `train.py`；复盘见 `docs/notes/训练日志记录开发复盘.md`。

## 一、需求复述

需求原文要点：ac 与 sac 算法训练过程中，目前仅保留 eval 的 json 结果，没有保存全部输出日志。要求向两个算法的训练代码增加训练日志保存设计：训练日志指控制台输出的所有内容，以 txt 格式保存，路径为对应运行目录 `data/.../train_log.txt`。

实现前与用户逐项对齐（文字问答），四项决策如下：

| 决策点 | 结论 |
|---|---|
| 日志内容口径 | 控制台输出**原样照录**，不加时间戳、分段标题等任何附加字段 |
| 捕获机制 | 程序内 tee 双写 `sys.stdout` 与 `sys.stderr`，控制台与文件各写一份 |
| 代码组织 | 沿用平行复制风格，`src/ac/` 与 `src/sac/` 各放一份同构 `log_tee.py`，不抽跨算法共享模块 |
| 记录生命周期 | 自输出目录创建起记录至进程结束；逐条 flush，中断不丢；写入模式**追加**，与 `eval_history.jsonl` 一致 |

范围限定：仅改两个 `train.py` 并新增各自目录下的小模块；`eval_demo.py` 及其余文件不动；正式、smoke、profile 三种运行一视同仁，均生成 `train_log.txt`。

## 二、总体设计

日志为"所见即所得"镜像：替换进程的 `sys.stdout` 与 `sys.stderr` 为 tee 流，每个 `write` 同时写回真实控制台流与日志文件并即时 flush。由此训练脚本自身的 `print`、第三方库（dm_control、torch 等）直写 stdout/stderr 的警告、未捕获异常与 KeyboardInterrupt 的 traceback 全部进入日志，且文件记录顺序即程序写入顺序。

```
print / sys.stdout.write / sys.stderr.write / traceback
        │
        ▼
   _Tee.write(text)
        ├── real.write(text)      # 原流，控制台行为不变
        ├── log.write(text)       # train_log.txt（追加）
        └── log.flush()           # 即时落盘
```

生命周期与接入点：

```
mkdir out_dir            # data/ac-<时间戳>[-smoke] 或 data/sac-<时间戳>[-smoke]
log_tee.start(out_dir / "train_log.txt")   # 先于 out=/cfg 等全部 print
训练主循环、eval 节点、DONE 行
log_tee.stop()           # main 正常收尾：恢复原流、关闭文件
```

正常结束时文件显式关闭；异常或 Ctrl+C 未走到 `stop()` 时，逐行 flush 已保证无缓冲滞留，traceback 经 stderr 在进程退出前入档，内容完整。

### 与既有存档的协同

训练目录内文件分工：`latest.pt` 与 `best.pt` 提供模型权重，`eval_history.jsonl` 提供可机读的 eval 数值序列，新增的 `train_log.txt` 提供完整人工可读的运行轨迹（cfg、逐 episode 进度、EVAL、DONE 及第三方警告）。txt 与 json 互补，不重复存储：json 行本身也在控制台输出中，故天然进入 txt。

## 三、模块与接口

### 3.1 log_tee.py

两算法目录下文件逐字节同构（`cp` 复制），模块名不与标准库冲突（沿用 profile 命名教训）。公开接口仅 `start(path)` 与 `stop()`，均幂等：

| 接口 | 行为 |
|---|---|
| `start(path)` | 以追加模式、`encoding="utf-8"` 打开 `path`；记录原 stdout/stderr；替换为共享同一文件句柄的两个 tee 流 |
| `stop()` | 恢复原 stdout/stderr；flush 并关闭文件；清空模块全局状态 |

内部 `_Tee(real, log)` 包装流的行为要点：

- `write` 先写原流再写文件并 flush 文件，返回写入字符数；若原流写入异常（如编码错误），异常照常抛出，与未接 tee 时行为一致，不静默吞错。
- `flush` 转发原流（维持原有缓冲策略）；`writelines` 逐行走 `write`。
- `isatty`、`fileno`、`encoding` 委托原流，避免依赖流属性的第三方代码在 tee 下行为变化。
- stdout 与 stderr 两个 tee 共享同一文件对象，两路写入顺序即程序调用顺序，行间不交错丢失。

文件句柄由模块全局持有，进程退出时由解释器清理关闭；配合逐条 flush，无论是否显式 `stop()`，落盘内容一致。

### 3.2 train.py 接入

`src/ac/train.py` 与 `src/sac/train.py` 各两处接入，结构一致：

| 接入点 | 内容 |
|---|---|
| 顶部 | `import log_tee` |
| `out_dir.mkdir(...)` 之后 | `log_tee.start(out_dir / "train_log.txt")`，先于 `out=` 与 `cfg` 两个 print |
| DONE 行之后 | `log_tee.stop()` |

两个 `train.py` 顶部 docstring 同步补充"控制台全部输出逐条 tee 到同目录 train_log.txt（追加）"。

## 四、可靠性边界与开销

- **目录创建前的输出不入档**：argparse 解析、import、环境构建发生在 `out_dir` 确定之前，无法（也不应）进入本次日志，属预期边界。
- **中断不丢**：逐条 flush 保证 Ctrl+C 或异常时已输出内容完整；模拟未捕获 KeyboardInterrupt（退出码 130）验证通过，日志含全部已 flush 行与 traceback。
- **缓冲乱序不影响文件**：管道重定向下 stdout 块缓冲、stderr 无缓冲，终端显示可能出现跨流乱序；文件按程序 write 调用顺序记录，内容全集完整，这与"控制台输出的所有内容"的需求口径一致。
- **追加语义**：同目录重复运行（时间戳到秒，极端同秒复用目录）时各段衔接保存，与 `eval_history.jsonl` 追加语义一致。
- **编码**：日志文件固定 utf-8；日志内容以 ASCII 为主，Windows 控制台 locale 编码差异不影响文件侧。
- **性能开销**：tee 每行增加一次文件写与一次 flush；训练输出频率为每 episode 或每 eval 节点一行量级，开销可忽略，不影响训练主循环。

## 五、运行与实测（本机 .venv CPU）

验证命令与结果：

```
.venv\Scripts\python.exe src\ac\train.py --smoke     # 退出码 0
.venv\Scripts\python.exe src\sac\train.py --smoke    # 退出码 0
```

ac smoke 生成的 `data/ac-20260908-112046-smoke/train_log.txt` 五行内容：

```
[ac-train] out=D:\...\data\ac-20260908-112046-smoke
[ac-train] cfg device=cpu seed=0 max_env_steps=600 ...
[ac-train] ep=1 env_steps=600 ep_return=38.245 ...
[ac-train] EVAL env_steps=600 mean_return=43.788 ...
[ac-train] DONE env_steps=600 episodes=1 ...
```

比对方法：进程 stdout 与 stderr 合并重定向至临时文件，去除行尾 `\r` 后与 `train_log.txt` 做 diff。ac 与 sac 两次验证均零差异，日志自首个 `out=` 行起即与控制台逐字一致。

附加单测（临时脚本置于 `data/`，验证后删除）：

- stderr 捕获与追加：两次 `start` 于同一文件，最终内容依次含 `first-line`、`stderr-line`、`second-line`，确认 stderr 入档与追加语义。
- 中断兜底：`start` 后打印两行并 `raise KeyboardInterrupt`，退出码 130，文件保留两行与完整 traceback。

正式运行方式不变，训练结束后在 `data/<算法>-<时间戳>/train_log.txt` 读取全量输出：

```
.venv\Scripts\python.exe src\ac\train.py
.venv\Scripts\python.exe src\sac\train.py
```

平台与复验：tee 机制不依赖平台特性，日志为固定 utf-8 文本；Linux 无头与 GPU 主机的完整训练仅按正式命令执行即可复验 `train_log.txt` 生成，无需额外参数或改动。
